# 用户管理功能设计

日期：2026-11-12

## 目标

为系统管理员提供独立的用户管理页面和安全的管理 API，支持：

- 分页查看、搜索和筛选用户。
- 创建用户并分配一种或多种角色。
- 修改显示姓名、角色和启用状态。
- 启用或停用用户。
- 管理员重置用户密码。

角色范围为 `system_admin`、`submission_operator`、`reviewer`、`author`、`auditor`，均支持多选。创建用户和重置密码时由管理员设置密码，目标用户随后必须修改密码。

## 非目标

- 不删除用户。
- 不修改用户名。
- 不新增、编辑或删除角色定义。
- 不改变现有作者授权、登录、密码修改和稿件权限模型。
- 不需要数据库迁移，复用现有 `users`、`roles`、`user_roles` 和 `auth_sessions` 表。

## 模块结构

后端新增独立用户管理资源，遵循现有 API、服务、模型和审计分层：

- API 层负责管理员权限、CSRF、请求与响应模型。
- 服务层负责用户读写、角色分配、密码策略、管理员保护、会话注销、事务和审计。
- 前端新增用户管理页面、API 类型与请求方法、管理员路由和导航入口。
- OpenAPI 与契约清单同步更新。

## API 契约

所有路径均位于 `/api/v1`，仅 `system_admin` 可访问。写操作要求 CSRF。

### `GET /users`

分页返回非删除用户。

支持：

- `page`、`page_size`。
- `name`：匹配用户名或显示姓名。
- `status`：`active` 或 `disabled`，不传入时返回全部状态。
- 白名单排序字段 `username`、`display_name`、`created_at`、`updated_at`、`last_login_at`，以及 `asc`、`desc` 顺序。

返回用户安全字段：`id`、`username`、`display_name`、`roles`、`status`、`must_change_password`、`last_login_at`、`created_at`、`updated_at`。不返回密码、密码哈希、会话或 CSRF 数据。

### `POST /users`

请求字段：

- `username`：去除首尾空白后长度为 1–64，使用现有规范化规则保证唯一。
- `display_name`：必填，最大长度 128。
- `password`、`password_confirmation`：必填，两者一致并复用现有密码强度校验。
- `roles`：至少一项，不得重复，所有角色必须存在。

创建后用户状态为 `active`，`must_change_password=true`，密码只保存哈希。成功返回 `201` 和安全用户响应。重复用户名返回 `409`，非法输入返回 `422`。

### `GET /users/{user_id}`

返回与列表一致的安全用户响应。不存在或已删除的用户返回 `404`。

### `PATCH /users/{user_id}`

允许提交以下至少一个字段：

- `display_name`。
- `roles`：至少一个有效角色，不得重复。
- `status`：`active` 或 `disabled`。

用户名不可修改。服务在同一事务中应用修改、执行管理员保护、记录审计并提交。停用用户时注销其全部现有会话；重新启用不恢复旧会话。

### `POST /users/{user_id}/reset-password`

请求字段为 `new_password`、`password_confirmation`，两者必须一致并通过现有强度校验。

成功后：

- 更新密码哈希。
- 设置 `must_change_password=true`。
- 注销目标用户全部现有会话。
- 返回 `204`，不返回任何密码或用户凭据。

管理员重置本人密码时使用相同流程，前端随后清除本地会话并进入登录页。

## 权限与管理员保护

所有接口在服务端验证系统管理员权限，前端隐藏入口不能替代后端授权。

服务层执行以下保护：

1. 禁止管理员将本人状态改为 `disabled`。
2. 禁止管理员从本人角色中移除 `system_admin`。
3. 任何修改后必须至少保留一名未删除、状态为 `active` 且拥有 `system_admin` 角色的用户。
4. 更新目标用户及当前启用管理员记录时使用数据库行锁，在锁内重新计算修改后的管理员集合，防止并发停用或降权绕过保护。

管理员仍可重置本人密码；该操作会注销本人当前会话并返回登录页。

## 一致性、错误与审计

- 创建用户、角色关联、状态更新、密码更新和会话注销在同一事务中完成。
- 角色代码批量查询并完整匹配，任一角色无效则整体回滚。
- 数据库唯一性冲突转换为安全的 `409` 响应。
- 已删除或不存在的目标统一返回 `404`，不暴露额外账号信息。
- 创建、资料/角色/状态修改、停用及密码重置写入操作审计。
- 审计前后摘要仅包含用户名、显示姓名、角色、状态、改密标记等允许字段，不包含密码、密码哈希、会话令牌或 CSRF 令牌。
- 列表排序使用白名单，筛选参数由 ORM 绑定。

## 前端设计

新增仅系统管理员可见的“用户管理”导航、路由和页面。

### 用户列表

展示用户名、显示姓名、角色、状态、是否必须改密、最后登录时间和可用操作。支持分页、姓名搜索、状态筛选和排序。

### 新增用户

表单包含用户名、显示姓名、初始密码、确认密码和五种角色多选。提交前检查必填项、密码一致性和至少一个角色；提交期间禁用按钮。

### 编辑用户

表单包含显示姓名、角色多选和启用状态。当前管理员编辑本人时，前端同时提供保护提示，但服务端保护仍是最终边界。

### 重置密码

表单包含新密码和确认新密码。重置其他用户后刷新列表；重置本人后退出到登录页。

新增、编辑及重置成功后复用统一的“保存成功”提示，显示 1 秒后自动消失。失败时保留现有表单并展示安全错误信息，不显示成功提示。

- 列表分页、搜索、状态筛选、排序和详情。
- 编辑显示姓名、角色、启用与停用。
- 停用和重置密码后的会话注销及必须改密标记。
- 自我停用、自我移除管理员、最后一名启用管理员保护。
- 安全审计内容及响应不泄露密码或会话数据。

- 用户列表、筛选和分页。
- 新增、编辑、角色选择、状态变更及重置密码请求。
- 表单校验、重复提交防护、错误显示和保存成功提示。
- 重置本人密码后的退出行为。
